# Whole-file HTTP chunked LOCAL transfer review

This is a read-only source review, distinct from unsupported legacy multipart fragment uploads and the permission-blocked modern `M` provider. No live upload, draft mutation, commit, or publication was executed. It does not establish a body-size cap, a cloud-proxy authentication cause, a successful bridge workaround, or deployed source parity.

**The pinned modern LOCAL application path accepts `request.content_length=None` and can write the entire request stream until EOF.** [RequestStreamParser](https://github.com/inveniosoftware/invenio-records-resources/blob/12ca933194d9f5c4ea15eacc72ec220ee2cec197/invenio_records_resources/resources/files/parser.py#L9) preserves `request.stream` and `request.content_length` directly. [FileResource.update_content](https://github.com/inveniosoftware/invenio-records-resources/blob/12ca933194d9f5c4ea15eacc72ec220ee2cec197/invenio_records_resources/resources/files/resource.py#L293) forwards both; `set_max_content_length` sets the per-request file-upload limit from `FILES_REST_DEFAULT_MAX_FILE_SIZE` (fallback10^10), so absent Content-Length does not remove the application limit.

[FileService.set_file_content](https://github.com/inveniosoftware/invenio-records-resources/blob/12ca933194d9f5c4ea15eacc72ec220ee2cec197/invenio_records_resources/services/files/service.py#L346) defaults `content_length=None`. Both classic LOCAL and the staged LOCAL uploader support it. [Transfer.set_file_content](https://github.com/inveniosoftware/invenio-records-resources/blob/12ca933194d9f5c4ea15eacc72ec220ee2cec197/invenio_records_resources/services/files/transfer/base.py#L80) skips the *preflight advertised-size check* only when length is absent, and still passes bucket `size_limit` to storage. [Staged FileUpload._upload](https://github.com/inveniosoftware/invenio-records-resources/blob/12ca933194d9f5c4ea15eacc72ec220ee2cec197/invenio_records_resources/services/files/upload.py#L413) calls `storage.save(stream,size=content_length,size_limit=prepared.size_limit)`. It aborts on FileSizeError, ClientDisconnected/OSError, and storage exceptions; finalize rechecks the actual written size against the current bucket limit and preserves the upload's immutable identity guard against concurrent replacement.

[PyFSStorage.save](https://github.com/inveniosoftware/invenio-files-rest/blob/140ef50fef4dea028d6ceb53cb51254eb5b6b355/invenio_files_rest/storage/pyfs.py#L237) passes `size=None` into [_write_stream](https://github.com/inveniosoftware/invenio-files-rest/blob/140ef50fef4dea028d6ceb53cb51254eb5b6b355/invenio_files_rest/storage/base.py#L229), which reads blocks until EOF and computes actual byte count and checksum. `check_sizelimit` still raises on limit overflow; exact advertised-size equality is unavailable with `size=None`. Exceptions remove the incomplete storage file. Therefore an apparently successful unknown-length stream could be truncated at a premature EOF without an advertised expected-size error. Exact expected local length, remote size/checksum and a fresh complete content stream remain mandatory outside the uploader.

**The front-end/WSGI condition remains unresolved.** Zenodo-RDM `uv.lock` pins Flask 3.1.3 and Werkzeug 3.1.9. [Werkzeug3.1.9 get_input_stream](https://github.com/pallets/werkzeug/blob/6604c3b8784ecc7cf5ac0b7412d916989b4c7d45/src/werkzeug/wsgi.py#L143) returns unknown length for HTTP `Transfer-Encoding: chunked`; it safely reads that stream only if the WSGI server supplies `wsgi.input_terminated`. Without that signal and without Content-Length it returns an empty stream. With the signal it enforces max content length during streaming. The public [Zenodo Nginx configuration](https://github.com/zenodo/zenodo-rdm/blob/9370acc127c643aff4c43c59cf163c2982f3201c/docker/nginx/conf.d/default.conf#L72) explicitly sets proxy HTTP1.1 and disables request buffering for chunked encoding; its uWSGI upstream also disables request buffering. Those source settings do not prove the live cloud bridge or WSGI server correctly decodes/signals this request.

A single bounded whole-body HTTP chunked attempt against the initialized LOCAL modern `/records/<id>/draft/files/<key>/content` endpoint is a source-compatible diagnostic candidate if root elects it. It must transmit the unchanged sealed whole file, not fragment PUTs or an `M` transfer. Suppress Content-Length, send valid chunked encoding through a client that frames it correctly, retain verified TLS and exact same-host bearer-token routing, and independently inspect the result before any commit. Any lost response needs GET reconciliation; an absent file, empty file, truncated file, checksum mismatch, or pending failed upload is not publication success. This review made no such request.

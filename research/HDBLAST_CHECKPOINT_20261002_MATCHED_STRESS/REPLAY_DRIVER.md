# Self-contained matched-stress replay

This replay driver is postrun packaging code. All prospectively frozen scientific inputs and gates remain unchanged. The public scientific freeze is `4a5dad8dda6d0a57a9cf88cc8b4a9b8feeaea45d`; full registration SHA256 is `4a1533fa7bf9df41cc635d76fa61a22b3aa119d8fbf215349fe09cf3ee54c893`.

Package `replay_stress.py` as `code/replay_stress.py`, and place both support files under `replay_inputs/`. The driver discovers the checkpoint from its own location. It needs no repository argument, Git checkout or network access. The support files are immutable inherited inputs with the hashes already specified by frozen `theory/SOURCE_PINS.json`; three other source-pin inputs are already included under `inherited/`. The driver constructs a tiny external path mirror for the unchanged tail-proof CLI.

Use Python 3.12 with the checkpoint's exact `requirements.txt` versions and Matplotlib 3.10.1 for the saved-data renderer. In this workspace the pinned executable is `/workspace/hdblast-cloud-setup/venv-frw/bin/python`. Run:

```
python CHECKPOINT/code/replay_stress.py --output FRESH_EXTERNAL_DIRECTORY
```

The output must be a fresh directory outside the source checkpoint. `--plan-only` performs input verification, isolation and source-mirror construction and records the exact twenty-two-command plan without executing any child command. It is a preparation check, not a physical replay PASS.

The full driver runs primary algebra, independent source-jet bridge, stress-tail algebra, exact pulse proof, independent finite-cutoff Ward algebra and validator guard tests normally and with `-O`, followed by one primary producer, one independent producer, normal/optimized validators, a saved-data summary into `fresh/report`, and nine saved-data figures into `fresh/figures`. Four final commands run the additional saved-mode audit and the separate future-proposal exact proof, each normally and with `-O`. The exact pulse certificates and global rational envelopes are authenticated as frozen inputs; their optional separate global-envelope derivation is not rerun by this twenty-two-command plan. Every child has a 1000-second wrapper timeout; physical producers retain their own 900-second frozen limit. Numerical-library thread counts are fixed at one and bytecode writes are disabled.

Frozen registration, independent own manifest, inherited inputs and support sources are checked before execution and after each command. If a final package `MANIFEST.json` exists, payload hashes and membership are checked too. Source and isolated work inputs are verified again on exit, including failure. Each child gets a persistent log and an execution receipt before launching. Dependency mismatches, command failures and timeouts retain a FAIL receipt; the driver stops without changing tolerances or rerunning failed experiments. All fresh result files receive output hashes. Actual planned, attempted and successful command counts are recorded.

Full success requires the actual original validation counts: 180 core comparisons, 108 baseline/anomaly/current comparisons, 72 direct density/pressure-versus-closed comparisons, 36 finite-K trace checks, 72 archive reconstructions, 72 reported Ward endpoints (36 fine gated), 36 Ward refinements, 180 core refinements, 288 continuum comparisons and 20 honestly classified controls. Normal and optimized validation evidence must agree apart from their optimization-mode field. Summary source hashes, all twelve saved-value rows, 36 finite-band points, normalization conversions, actual comparison/residual/resource maxima and counts are independently checked against the input data. All nine figure file hashes, exact membership, summary/renderer hashes, postrun scope and Matplotlib version are checked against rendering provenance.

The prior sixteen- and eighteen-command preparations are retained under `pre-extension-16/` and `pre-extension-18/`. The extended preparation in this staging directory passed 28 synthetic/static driver checks normally and optimized. Its isolated plan-only verification used the pinned environment, verified all frozen sources before/after, and executed zero child commands. The default shell environment's NumPy mismatch was rejected and retained as an environment preflight failure, with zero physical commands. No duplicate physical replay was executed while preparing this driver.

The additional saved-mode audit is classified as post-run saved-data reconstruction, with 24 snapshots, 576 quantity sums, 72 Ward endpoints, 36 ledger refinements and 98,304 panel moments. Its actual source, raw archives, mode-results hash, runtime and optimization mode are checked; normal and optimized numerical evidence must agree. It adds no mode evolution. The separate `theory/second_order` proof is an **unregistered, numerically unexecuted future proposal**: only 21 exact identities and eight algebraic mutations with nine local hash-pinned references are checked. The default CLI needs no checkout. Its proof JSON has no optimization field, so the normal/optimized modes are recorded by the driver command receipts. This proof cannot count as a successful second-order physical experiment.

Long-double padding can change NPZ byte hashes across runs. Each run's own NPZ is authenticated and reconstructed by its validator; this driver does not compare NPZ bytes across independent executions. Passing remains limited to fixed-geometry linear minimal stress/current susceptibility; it establishes no coupled evolution, stability or heating result.
